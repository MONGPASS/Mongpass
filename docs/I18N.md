# Internationalization

## Current State

MongPass is designed primarily for Mongolian-speaking users in Korea.
`src/app/layout.tsx` declares Mongolian as the document language and loads
Inter with Latin and Cyrillic subsets. Korean system fonts are available as
fallbacks.

Most current interface text is embedded in components and domain constants.
This is sufficient for the Mongolian-first prototype, but it is not the final
multilingual architecture.

The business workspace (`/biz`) and its preview use Mongolian copy. The
platform administrator workspace (`/admin`) uses Korean. Shared management
components select copy through `AdminLanguage` and the business messages in
`src/lib/admin/businessMessages.ts`; business-specific pages also contain
Mongolian strings directly. User-generated content is preserved as entered.
This is an incremental bridge rather than a complete locale system; the
three-locale structure below remains planned. Native-speaker review of the
business UI is still needed.

## Target Locales

| Locale | Purpose |
| --- | --- |
| `mn` | Primary Mongolian interface |
| `ko` | Korean institutions, partners and bilingual users |
| `en` | Contributors and international users |

## Proposed Structure

```text
src/i18n/
├── config.ts
├── getMessages.ts
└── messages/
    ├── mn.json
    ├── ko.json
    └── en.json
```

Message keys should describe meaning instead of copying source text:

```json
{
  "community.createPost": "Create post",
  "shop.registration.pending": "Waiting for approval"
}
```

## Contribution Rules

- Mongolian is the source language for community-facing copy.
- Do not concatenate translated fragments; use complete messages.
- Keep dates, currency and numbers locale-aware with `Intl`.
- Add all three locale keys in one pull request when introducing new UI.
- Ask a native speaker to review user-facing translations.
- Preserve user-generated content in its original language.

The locale extraction is tracked in the Roadmap and should be completed
incrementally by feature area.
